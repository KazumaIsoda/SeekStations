# SeekStations

# システム概要
任意の出発地点から、○○分以内に到達可能な駅を検索できるアプリケーションを構築する。

# 構築の動機
仕事でインフラ（AWS）・バックエンド（spring boot）・フロント(react)・CI/CD（Github Actions）を一通り触ったので、
試しにそれらを駆使してアプリケーションを作ってみたいと思った。

# このアプリケーション構築の背景
もともと、旅行から帰った際に残ったICカードの残高（500円くらい）をちょうど自宅からの往復で使いきれる駅を探したかった。
ただ、実現にあたって駅ねっとAPIなどの外部APIを複数調査したが、金額から到達可能な駅を検索できるAPIはなかった。
ないならアプリ側で補完できるのではと思ったが、以下の処理になる。

例：
①駅すぱあとAPIの範囲検索を実行（例：30分以内に到達可能な駅を一覧取得）
②取得した駅一つ一つに対して、経路取得APIを実行（料金取得のため）
③指定した金額に一致する駅をアプリ側で表示

これの問題点は、範囲取得した結果が多ければ多いほど、実行する経路取得APIの数が増えること。
例は30分だったが、例えば3時間にすると膨大な数の駅に対して経路取得APIを実行するのでコストが増える。

本アプリケーションの目的は、あくまでインフラ～アプリを通貫した個人開発なので、  
アプリ自体の実装の過剰な複雑化は望まない。

そのため、趣旨を変更して、
「指定の場所から○○分以内に行ける駅を探す」
アプリケーションをテーマにする。（運賃検索は行わない）

# アプリの使用目的
「現在地や任意の場所から、どこか違う場所へ行ってみたい。でもあまり遠くまでは行きたくない...
例えば、ここから30分以内に行ける場所ってどこだろうか？」
そんな、ふと行ったことない駅を冒険したい時に役立てたい

# このアプリで最低限実現すること
検索画面
①任意の駅を入力し、指定の時間を入力する
②検索ボタンを押して実行する

結果画面
①任意の駅から指定の時間内に到達可能な駅を一覧で表示する
②それぞれの駅の経路の路線を表示する

# できれば実現したいこと
検索画面
①現在地情報を取得し、近くの駅を表示・選択可能にする
②マップに現在地または指定の駅を表示する
③最大乗り換え回数を指定
④新幹線・有料特急の利用の有無を指定

結果画面
①取得結果の駅をマップで表示
②それぞれの駅の到着までの時間を表示する
③冒険の参考のために、駅の口コミを投稿・表示できるようにする。（無秩序な書き込みを防ぐために、アプリ側で制御をかける 例：この駅の特徴は？→①にぎやか ②住宅街 ③公園がいい ④おいしいラーメン屋あり）

# このアプリで実現「しない」こと
①会員・ログイン機能の実装
→セキュリティリスクのため。このアプリではユーザーごとの情報を保持しない
②目的地までの運賃の検索
→前述の通り、既存の経路取得APIを使用する際の実行コストを考慮し、行わない

- AWS
  - IaCはTerraform
  - ALB・ECS・ECR・Route53。httpsでの構築なので証明書発行にACMも必要？
  - ECSは、フロントとバックエンドで分ける？（未確定）
  - 口コミ機能を実装するのであれば、RDSも必要になると思われる
  - 最小権限の原則を遵守

## アプリ側
- バックエンド
    - Spring boot
    - java 25
    - ドメイン駆動設計？

- フロントエンド
    - Next.js
    - Typescript

- DB(口コミ用)※現時点では不要
    - postgres(RDS)

## CI/CD
- Github Actions
    - インフラ側は、Terraform Plan・Applyそれぞれのワークフロー
    - アプリ側は、ECRにイメージをpushするワークフロー
